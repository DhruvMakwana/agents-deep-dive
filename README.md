# Agents, Deep Dive — blog source

MkDocs Material site. Source of truth is `docs/*.md` + `mkdocs.yml`.

## Local preview

```bash
python3 -m pip install --user -r requirements.txt
mkdocs serve
```
Open http://127.0.0.1:8000 — hot-reloads on save.

Content pages embed real code live from the [`agents-cookbook`](https://github.com/DhruvMakwana/agents-cookbook) repo at build time (via `pymdownx.snippets`' `url_download`), so building requires network access. If you're on macOS with the python.org installer and see `CERTIFICATE_VERIFY_FAILED`, run:
```bash
python3 -m pip install --user certifi
export SSL_CERT_FILE=$(python3 -c "import certifi; print(certifi.where())")
```
(GitHub Actions' Ubuntu runners already ship a valid CA bundle — this only affects local macOS builds.)

## Adding, editing, deleting content

One Markdown file per page under `docs/`, one line per page in `mkdocs.yml`'s `nav:`. No CMS, no database, no build pipeline beyond MkDocs itself. The revision page (`docs/revision.md`) is generated by `scripts/generate_revision.py` from every page's TL;DR/quiz/flashcard content — re-run it after editing any of those, then rebuild.

## Publishing to GitHub Pages

This folder (`blog/`) is meant to become the **root of its own GitHub repo** — that's what `.github/workflows/deploy.yml` assumes.

1. Push the contents of this `blog/` folder to a new repo, e.g. `github.com/<you>/agents-deep-dive`, as its root.
2. In `mkdocs.yml`, confirm `site_url`, `repo_url`, `repo_name` match that repo.
3. In the repo's **Settings → Pages**, set source to the `gh-pages` branch (created automatically by the first Action run).
4. Push to `main` — the site builds and deploys automatically from then on.

## One-off manual deploy (no GitHub Actions)

```bash
mkdocs gh-deploy
```

## Standing rules for this project

See `../PLAN.md` section 5 ("How each page gets researched") and `../BLOG-PROJECT-LEARNINGS.md` for the house rules carried over from the RAG project: run every code claim in a fresh venv, state findings as facts (never narrate the build), report negative results honestly, research each page fresh against live sources, and stamp every fast-moving claim (versions, protocol specs, benchmark scores) with the date it was checked.
